# Unity 打开 Visual Studio 故障与修复

2026-11-05 已修复并通过 Unity 实际操作验证。

调试器在 Unity 官方启动器创建的 VS 进程中捕获了失败。VS 以低完整性运行，加载 `C:\Users\25786\AppData\Local\Microsoft\VisualStudio\18.0_36605d2e\privateregistry.bin` 时，`NtLoadKeyEx` 返回 `0xC0000022`，随后 `RegLoadAppKeyW` 返回 Win32 错误 5。直接启动、能加载项目的 VS 进程具有中等完整性。

同机 Flappy Bird 项目中的 `COMIntegration.exe` 与本项目文件 SHA-256 完全相同。本项目的启动器从包缓存目录继承了低完整性标签，正常项目中的文件采用默认中等完整性。修复把已校验的官方启动器恢复为中等完整性，并在 `Library\PackageCache` 设置可继承的中等完整性标签。包更新时，在该目录中生成的文件会继承这一设置。整个缓存目录被删除并重建后，需要重新核对继承标签。官方二进制的内容哈希保持一致。

验证结果

- VS 关闭时，在 Unity 项目面板双击 `States.cs`，启动单个 VS 实例，加载 `ZaoMengXiYou3.slnx`，打开脚本。
- VS 已运行时，在 Unity 双击 `ActorBoostTrail.cs`，复用同一实例，活动文档归属 `Assembly-CSharp.csproj`。
- 官方启动器将 `Bird.cs` 定位到第 44 行。VS 显示引用计数。仅在 VS 内存缓冲区插入的临时测试错误，实时出现在错误列表中，编号 `CS1029`。随后撤销临时编辑并核对文件哈希，磁盘内容一致。
- 悟空预制体进入 Unity Prefab Mode，测试后返回原场景。
- 另一项目的官方启动器也加载了 `Flappy Bird.slnx`，`GameManager.cs` 归属该项目的 `Assembly-CSharp.csproj`。

之前的直接启动方案漏掉了资产类型过滤，且 `/Edit` 使脚本进入杂项文件模式。相关代码和临时诊断脚本已撤出 Assets，保存在 `output/VSUnityRepair-20261104` 的归档目录中。缓存重建、VS 组件配置刷新和重新安装曾改善直接启动，但 Unity 原来的启动错误仍然存在，直到修复启动器的完整性标签。

故障现场见 `output/VSUnityRepair-20261105/cdb/helper-interactive.txt`，修复后的官方启动器日志见同一诊断目录下的 `official-launch-medium.txt` 和 `official-line-test.txt`。历史 VS 组件缓存备份保留在 `C:\Users\25786\AppData\Local\Microsoft\VisualStudio\18.0_36605d2e\ComponentModelCache.backup-20261104-193404`。
