# 后续关卡搭建

以下路径都相对于 Unity 项目根目录。第一关仍使用 `Assets/Level1/Level1CS` 的旧实现，不需要迁移。

## 1. 创建场景

在 Unity 菜单选择 **造梦西游 → 创建关卡场景**，输入关卡编号，点击“创建并打开新关卡”。工具从 `Assets/Projects/SceneTemplates/LevelTemplate.unity` 复制，生成 `Assets/Projects/Scenes/LevelNScene.unity`，并自动加入启用的构建场景列表。若当前场景未保存，Unity 会先询问是否保存。

工具绝不覆盖已有场景，默认选择首个空闲编号。当前项目已有 `Level3Scene` 至 `Level9Scene`，制作这些编号前应先确认原内容，按需要将原场景另存备份并改名，再用对应编号创建。场景名保留 `LevelNScene` 格式：地图、胜利后的“下一关”和存档统计都按它识别关卡。

## 2. 替换环境与摆放位置

新场景初始沿用第二关环境与配置。替换 `LevelTwoEnvironment` 预制体实例（层级中的原名为 `BackGround`）的背景图片和地面碰撞体，摆放玩家出生点、出口点、Boss 出生点与冲撞边界点。做成当前关卡自己的环境预制体或预制体变体，关卡专属调整也可以保留为场景覆盖。

`LevelSetup/LevelTwo` 上挂的是通用的 `StageManager` 和 `StageEnemyManager`，原来的物体名称保留了下来。位置点在 `LevelSetup/transforms`：`enemyBornY` 是 `tran`，目前同时用作玩家出生位置和小怪出生高度；`exit` 是出口位置，`TitanBorn` 是 Boss 出生点，`TitanLungeLeft/Right` 是 Boss 冲撞边界。名字保留自第二关，其他关卡可以按用途改名，组件使用引用而非名字查找。

`CameraRig` 中相机负责移动，边界点留在固定的根节点下。调整 `CameraManager` 的 `cameraEdgeLeft`、`cameraEdgeRight`：数组按波次顺序对应，数值表示**相机中心能到达的位置**；两边数组长度一致，左边不能大于右边。

镜头除了水平跟随，还会在玩家跳到**镜头中心以上**时竖直跟随，参数都在 `CameraManager` 上：`verticalFollow`（开关）、`verticalFollowSpeed`（向上跟随速度）、`verticalReturnSpeed`（落地后回落速度）、`verticalTriggerOffset`（相对基准高度触发，负数可提前触发）、`maxRise`（相对摆放高度最多升多少）。基准高度取相机在场景里的摆放 Y，不需要额外配置；不需要竖直跟随就关掉 `verticalFollow`。

## 3. 配置波次和敌人

在 `LevelSetup` 的关卡管理器上调整：

| 配置 | 用途 |
| --- | --- |
| `maxWave`、`leftEnemyMax`、`rightEnemyMax` | 波数及每波左右侧小怪总数，两侧数组长度均等于 `maxWave` |
| `firstEnemyDelay`、`enemyDelay`、`enemyMax` | 开波等待、刷怪间隔、场上同时存在的小怪上限 |
| `bossBornDelay`、出生点与出口引用 | Boss 入场等待与关卡位置配置 |
| `StageEnemyManager.enemyPools` | 每项填敌人 `prefab`、对象池 `poolSize`、抽取权重 `weight` |
| Boss 预制体与左右边界点 | 当前关卡的 Boss 及活动边界 |

普通关卡可以直接使用 `StageManager` 和 `StageEnemyManager`，不用再为每关写一套同样的刷怪脚本。只在有新关卡机制时扩展。新的 Boss 若需要接收活动边界，实现 `IEnemyArenaBounds.SetArenaBounds(float left, float right)`，由敌人管理器注入本关左右边界。

## 4. 沿用共用系统

`Assets/Projects/Prefabs/Level` 下的 `PlayerSystem`、`BattleUI`、`CameraRig`、`LevelSetup` 负责共用逻辑。角色切换、技能特效、冰冻与中毒、金币、头像和状态条、胜败统计与保存沿用现有实现，不需要逐关重写或重新布置 UI。

| 预制体 | 包含内容 |
| --- | --- |
| `BattleUI` | 原 Canvas 全部内容、UIManager、EventSystem，保留原布局和按钮引用 |
| `PlayerSystem` | PlayerManager、GoldManager，以及已有角色与技能效果预制体引用；实例原名为 PlayerManager |
| `CameraRig` | Main Camera、CameraManager、每波固定的镜头边界点 |
| `LevelSetup` | 通用关卡流程、可配置敌人池、Boss、出生点与出口配置 |
| `LevelTwoEnvironment` | 当前第二关的背景与地面，供复制或制作关卡专属变体 |

当前第二关已经使用这些预制体实例。共用预制体内部引用已经保存，场景中三个管理器引用也已接好；自己在空场景中摆放这套预制体时，`StageManager` 会在启动时补齐 UI、角色系统与主相机引用。每个场景保留一套角色系统、关卡系统、战斗 UI 和主相机即可。

专属敌人、波数、边界和地形在新场景中覆盖；只在确实要影响所有关卡时才 Apply 到共用预制体。`BattleUI` 保留现有布局。

`MenuScene`、`MapScene`、`SkillScene`、`VictoryScene`、`DefeatScene` 继续共用，不复制到每一关。新增超出现有地图范围的编号时，还需要为 `MapScene` 配置对应入口按钮：放入 `Map.buttons` 对应位置，并将点击事件绑定为 `Map.EnterLevel(关卡编号)`。工具加入构建列表不会替你增加地图按钮或跳过关卡解锁条件。

## 5. 收尾

保存新场景，确认预制体引用、出生/出口点、波次数组、相机边界和 Boss 边界已按本关设置；再自行检查开局、换波、Boss 入场、胜败与地图入口。以后大部分关卡工作就集中在环境、敌人玩法和这些配置上。
